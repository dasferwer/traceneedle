# Внешняя оценка группировки

Набор: [HDFS_2k Loghub](https://github.com/logpai/loghub/tree/dd61d0952749ee7963bde24220d1be5ede023033/HDFS),
commit `dd61d0952749ee7963bde24220d1be5ede023033`;
SHA256 `729df59774e3dde934044028546d2a55d5e3d4370b9d12fcebbe4c087b2bf7b4`.
Источник представляет логи реальной распределённой системы с внешними
`EventId`/`EventTemplate`; текущие настройки Drain не выбирались по этим меткам.
Меткам сопоставлены результаты API/worker, метки не отправляются модели.
Использование — исследовательская проверка по условиям
[Loghub license](LOGHUB_LICENSE.txt), не MIT; сырые данные не включены в репозиторий.
Источник и публикация: Jieming Zhu, Shilin He, Pinjia He, Jinyang Liu,
Michael R. Lyu. *Loghub: A Large Collection of System Log Datasets for AI-driven
Log Analytics*. ISSRE, 2023. [Авторы/репозиторий](https://github.com/logpai/loghub).

Все 2000 исходных строк проверяются по checksum; в API отправлены 1998.
LineId 1579/1581 исключены исключительно по действующему ограничению длины
message (2476/2480 символов > 2000), без обрезки текста или отбора по меткам.
Остаются 14 внешних шаблонов. Content неизменён; исходное время заменено
недавними искусственными метками, чтобы пройти настроенную границу late.
Поэтому это проверка шаблонной группировки, не точности инцидентов/регрессий
или поведения реальных временных рядов.

Порядок — исходный LineId. UUID имеют общий случайный префикс и возрастающий
LineId в младших битах: worker сортирует записи одного ingest по received_at/id,
поэтому случайные UUID не перемешивают порядок. Два HTTP ingest по 1000/998 строк,
один последовательный клиент. Drain остаётся `sim_th=0.85`, `max_clusters=1000`,
тот же normalized(), без дополнительного маскирования block/IP/port.
Для каждого измерения создаётся свежая изолированная схема и пустой miner_state;
перенос состояния предыдущего запуска меняет результат и запрещён протоколом.

## Результат 09.10.2026

На macOS arm64, Python 3.12.13, PostgreSQL 17/pgvector, реальных локальных HTTP
API и worker получено 1369 групп для 14 шаблонов:

| Метрика | Значение |
|---|---:|
| Adjusted Rand Index | 0,060883 |
| Pair precision | 1,0 |
| Pair recall | 0,035830 |
| Ложно объединённые пары | 0 |
| Пропущенные пары одного шаблона | 245686 |
| Время ingest + ожидание + чтение 1998 событий | 25,337 с |
| Пиковый RSS evaluator (macOS ru_maxrss) | 125845504 байт |

Высокая pair precision сопровождается низкой recall: один внешний шаблон
разбивается на множество групп. Число итоговых групп превышает лимит 1000
активных кластеров, поэтому на длинной последовательности возможно вытеснение
и создание новых идентичностей. Этот запуск не отделяет вклад вытеснения от
вклада строгого порога/немаскированных переменных. Порогов приёмки качества на
этом наборе не заявлено; метрики не используются для настройки и не означают
пригодность группировки для production HDFS. Задача retention сохраняет данные
поддерживаемых сравнений и не «улучшает» score удалением неудобных событий.
RSS относится только к evaluator, память API/worker/PG не измерена этой цифрой.

## Воспроизведение

Сначала поднимите отдельные API и worker с пустой схемой/miner_state. Для
late=60 минут искусственный диапазон 1998 секунд помещается в поддержку.
Сохраните обязательный license notice рядом с скачанным датасетом:

```sh
curl -fsSL https://raw.githubusercontent.com/logpai/loghub/dd61d0952749ee7963bde24220d1be5ede023033/LICENSE -o LOGHUB_LICENSE
curl -fsSL https://raw.githubusercontent.com/logpai/loghub/dd61d0952749ee7963bde24220d1be5ede023033/HDFS/HDFS_2k.log_structured.csv -o HDFS_2k.log_structured.csv
API_URL=http://127.0.0.1:60260 API_KEY=local-demo-key \
uv run python -m scripts.evaluate_real_logs HDFS_2k.log_structured.csv
```

Вывод — JSON с checksum, фильтрацией, метриками и средой. Скрипт отказывается
от изменённого файла; случайные префиксы служат только изоляции service/ID.
Поддержка нескольких независимых реальных семейств логов, отдельный tuning/dev
набор и измерение памяти при росте уникальных шаблонов остаются дальнейшей
работой. Для проверки нового алгоритма понадобится новый holdout, этот набор
уже просмотрен при оценке текущего поведения.

Повтор после полного сброса отдельной схемы/miner_state дал точно те же ARI,
pair precision/recall, 1369 групп и число ошибочных пар; время 26,556 с.
